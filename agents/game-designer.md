# Game Designer（游戏设计）

## 开始前

- 阅读 [需求大纲](../Human/Human.md) 和 [角色、剧情、战斗大纲](../Human/GameContent.md)；第一章对白与演出同时读 [第一章稿件](../Human/Story_01.md)。区分原始设想、后续明确修订与已实现内容。
- 规划阶段工作时核对需求、当前实现和验证结果；历史测试结果和待办状态不作为当前事实直接复用。
- 设计战斗机制时读 [Battle 规则与接口](../features/battle/README.md)；编辑正式内容前读 [内容编辑](../content/campaign/README.md)，修改队伍或章节流程时读 [Player Mode](../game/player/README.md)。

## 设计与内容落地

- 先明确玩法大纲与关卡设计：场景、学习目标、路线、关键波次、角色职责和通过标准；未确定的选择标为待决策，再据已确认方案制作地图、对白与引导。
- 地点、角色装备、剧情动机与战斗任务保持一致；新机制明确玩家要做的决策和失败后的恢复方式。
- 优先通过 `content` 编辑内容：角色／敌人／技能使用 `.tres`，关卡／波次／背景使用 CSV，对白使用 Markdown，地形／路线使用地图场景。字段与语法以内容编辑文档为准。
- 产品界面只呈现必要状态、功能和操作结果；操作文档放 README，调试描述放开发工具。
- 新增通用规则或编辑工具时同时读取 [程序角色](programmer.md)；制作视觉资产时同时读取 [美术角色](artist.md)。

## 验收

- 剧情在 Story Test 检查，战斗在 Game Test 检查，章节衔接与存档在 Player Mode 检查；内容加载验证方式见内容编辑文档。
- 固定命令回放通过只证明存在可行操作方案；难度、节奏、引导和策略空间需要实际试玩验证。
- 规划写清优先级、交付物、验收门槛与待决策项；区分功能实现、内容完成和体验验收，记录尚未验证的部分。
