# 角色与敌人图集生成规范

本规范记录项目已确认的角色素材生成与交付要求。角色身份、职业和剧情以 [GameContent.md](../Human/GameContent.md) 及用户后续明确修订为依据；资源归属遵循 [架构约定](architecture.md#资源归属)。生成素材与接入游戏分别处理，生成任务本身不修改战斗配置或数值。

## 图集规格

| 项目 | 要求 |
| --- | --- |
| 格式 | PNG，RGBA，真实透明背景 |
| 最终尺寸 | 1024×1024 px |
| 网格 | 4行×4列，每格256×256 px，无可见网格线 |
| 行 | 每行一个角色／敌人，同一行保持身份、服装、装备、主色和体型一致 |
| 间隔 | 相邻单元之间至少20px完全透明区域；各格四边至少10px透明留白 |
| 推荐安全区 | 包含武器、头发、尾巴、披风的完整主体不超过232×232 px，各边至少12px留白 |
| 锚点 | 同行脚底／主体底部基线一致；当前导出基线为单元内y=244，像素主体位于其上方 |
| 数量不足4人 | 仅在请求未安排满4行时保留空行，空行必须完全透明，不复制角色填满 |

20px是透明隔离带的最小值，不是可见角色间距离必须恰好20px。不能用黑底、白底、棋盘格或其他纯色背景代替透明通道。

## 四列姿态与朝向

| 类型 | 第1列 | 第2列 | 第3列 | 第4列 |
| --- | --- | --- | --- | --- |
| 我方角色 | idle_front_left | idle_back_left | attack_front_left | attack_back_left |
| 敌人 | walk_front_left | walk_back_left | attack_front_left | attack_back_left |

- `left`始终指主体面朝画面左侧。`front_left`朝左下，显示脸／面具及胸部；`back_left`朝左上，显示后脑／兜帽背面及躯干背面。后视角需要真实背面结构。
- 敌人的前两列必须有明确的迈步、重心前移或多足移动姿态，不能沿用静止待机。这里每列是一幅姿态，不表示完整逐帧行走动画。
- 攻击与待机／行走要可辨认；医疗角色表现治疗动作，术师与辅助表现施法动作。
- 统一使用`attack`拼写，早期提示词中的`attach_front_left`按`attack_front_left`理解。
- 这些名称定义图像语义。现有`ActorAppearance`按图集行号和四列顺序取图；敌人使用walk语义不要求修改运行时接口。

## 画风与角色设计

采用精细高清Q版战术RPG插画：清晰轮廓、干净线条、细腻手绘明暗、统一头身比例。使用已确认图集作为画风和身份参考，生成前先实际查看参考图。未要求更换身份设计时，保留可识别的发型、服装、装备与配色。

当前画风与材质参考为`hero-atlas-03-v2.png`。整体配色柔和、降低饱和度，使用温暖象牙白、皮革与旧金属衬托各角色主色；保留红／黄／蓝／紫等识别色，避免鲜艳纯色大面积铺满服装。

各角色使用可区分的主色，并通过体型、职业装备和剪影进一步区分。性别与形态必须符合设定：阿五、胡胡、浮白等男性角色须保留男性表达；小黄是四足宠物猫；未知性别的遮面神秘人用兜帽、全脸面具和覆盖服装隐藏性别线索。不能把身份缺失自行补成明确性别。

## 主体与特效边界

全部输出完整主体，武器、帽子、头发、披风、尾巴和工具均不能裁切、跨格或与邻格重叠。同一行使用一致的主体比例和缩放系数，不因攻击武器伸展而单独缩小攻击姿态中的身体。

武器优先使用短、紧凑的设计，并弯肘持于身体附近。01／02修订采用短枪管与短枪托的狙击步枪、短剑、短柄长枪和宽刃短重剑；用瞄准镜、枪尖、刃宽与装备保留职业识别。不能通过横向伸直手臂和长武器填满整格。生成提示词可将整件步枪／短剑长度约束为人物全高的一半、长枪约为三分之二，最终仍以完整入格和合理体态验收。

身体图集中不加入大型刀光、弹道、枪口火焰、治疗光泡、漂浮加号、爆炸或其他脱离主体的特效；特效另行制作。时空编织者的细线等必要设计标识可紧贴双手／工具保留，但不能扩大到主导整格的效果。

不加入地面阴影、场景、底座、姓名、姿态标签、文字、水印、UI或可见网格。符文与装饰使用抽象图形，避免可读文字。

## 生成与导出

1. 生成前确定身份清单：每行是谁、身份与职业、性别／形态、主色、装备、四列姿态、参考图和目标路径。角色表顺序与实际图集行号保持一致。
2. 默认使用内置imagegen生成原始图像，显式要求真实透明背景。每次生成和修订均保存实际使用的完整提示词与参考来源。
3. 先检查原图的身份、数量、姿态和完整轮廓。原图已经裁掉的身体或武器需要修订／重生成，不能靠缩放补回。
4. 不假设生成器会返回精确的1024×1024或理想等分布局。按实际主体边界确认分区，保持纵横比，在各行内使用相同缩放系数，统一锚点后排入最终4×4网格；避免直接按原图四等分切断脚或武器。
5. 确定性后处理限于切片、透明边缘／孤立杂点清理、等比缩放和排版，不用程序绘制占位角色替代生成素材。不能为去噪误删武器尖端、细线或其他设计细节。
6. 验证最终PNG后再保存交付清单。只有被实际检查过的约束才能标为通过。

## 文件、版本与清单

- 原始素材与交付图集存放在`Human/StarterContent/character/`的任务子目录；例如`game-content-20261026/hero-atlas-03-v2.png`。敌人同目录以`enemy-atlas-*`区分。
- 修订默认使用`-v2`等版本后缀并保留旧版；只有明确要求替换时才覆盖已有文件。清单需明确当前版本和每行角色。
- 每张PNG旁保存同名`.prompt.txt`，包含实际完整提示词、修订提示词与参考来源，不仅保存摘要。
- `README.md`记录每张图的行号、角色／敌人、主色、职业或战斗职责；敌人另记录推荐登场关卡。`manifest.json`记录文件名、尺寸、模式、行列表、源图位置、源图及最终图SHA-256、后处理分区与验证结果。
- 保留生成器原件，记录其实际位置。中间副本、处理脚本、截图与一次性验证输出统一放在根目录`temp/`，并保留`temp/.gdignore`；最终交付和正式游戏不能依赖临时目录。
- 正式接入时再按稳定内容ID整理至`content/characters/`或`content/enemies/`，通过外部appearance配置引用。生成任务不自行改动正式角色ID、数值或波次。

## 验收

**自动检查：** PNG为1024×1024 RGBA；4×4每格256×256；每个预期单元有主体；指定空行完全透明；每格四边10px隔离带alpha为0；文件、提示词、行号清单和校验值相符。

**逐张目视检查：** 请求角色与画面身份相符；性别／形态、主色、职业装备正确；同一行四姿态一致；前视角与后视角正确；敌人明确行走；攻击／治疗／施法动作可辨；脚底锚点和身体比例稳定；所有主体完整，无串格、裁切、明显杂色边缘或多余特效。

**逐格检查武器：** 按运行时的256×256等分区域实际切片查看，确认每件武器从握柄到尖端连续完整，邻格没有孤立剑尖、枪管或其他碎片。旧`hero-atlas-02.png`曾将Sugar的剑切开，剑尖混入邻格；透明边距检查仍能通过，因此必须用逐格目视检查补足。原图发生跨格／缺失时，应重新设计短武器并生成，而不是只把切坏的单元缩小。

尺寸与间隔检查不能替代语义和画面检查。发现不符时修订或重生成，交付说明中如实记录仍未满足的约束。
