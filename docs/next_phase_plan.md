## 当前判断

项目已完成开发工具、基础塔防规则和第一章流程的技术闭环，进入“正式内容制作与体验验收”阶段。下一阶段建议以第一章可交付试玩版为目标：先完成第一关正式样板，再复制经过验证的制作方式打磨其余两关。

现阶段主要问题是内容与体验的完成度，以及编辑、验收流程的收口。现有架构可以继续承载这轮工作；没有证据表明需要先做大规模重构。

## 当前差距与风险

### 1. “能通关”与“第一章设计完成”仍有距离

本次固定命令回放三关全部胜利，模拟时间约 191 / 203 / 210 秒，基地生命均为 5。这证明已有一套有效操作方案，不能证明初见难度、策略空间或节奏已经合适。

第一关已有第二条突破路线，但当前新手提示仅是可关闭的两行文字。尚无本次真人试玩证据说明玩家能够自主完成选人、选格、朝向确认、技能和撤退。

第三关已实现 210 秒修复目标，并要求清理剩余敌人。应继续验证“等待计时”期间是否始终有值得做的决策，避免只延长关卡时长。

### 2. 战斗场景与剧情地点的视觉联系偏弱

本次真实窗口截图中，第一关剧情已呈现上海家中的异常裂隙，战场仍以通用黄褐色地块、石墙和红蓝线框端点为主。“家中异常”的地点与叙事尚未充分落实到战斗场景。建议保留战术可读性，围绕室内布局、门口和裂隙建立地点识别，再决定具体美术方案。

同一段剧情仍写大星“抄起长柄伞”，新角色图中持剑；角色装束与现实家庭背景也需要统一解释或调整。先确定文本与资产表达的一致性，再扩大内容生产。

### 3. 资产替换正在进行，不能把替换引用当作最终验收

开始分析时已存在多处未提交资源改动，包括角色图集、姿态/头像配置、敌人外观、背景映射及 Art Test；新背景 PNG 和敌人目录也有未跟踪文件。分析期间还观察到旧背景文件删除及测试文件变化，说明当前工作区快照仍在变化。

本规划不清理、不提交这些改动。资产完成任务需要明确检查：四姿态顺序、朝向、透明边缘、切片、显示比例、头像、剧情放大清晰度、正式和开发入口引用，以及新文件是否完整纳入交付。

旧资源只有在确认正式内容、开发样例和测试都不再引用后才能删除。

### 4. 剧情编辑有解析和预览，缺少直接编辑的工作流

Story Test 已有正式剧情选择、重载、重播和错误显示；正式对白仍需手写 MD 元数据。下一步应改善作者操作效率，而非重新实现剧情运行器。

建议先补“打开当前源文件、背景/角色/说话人 ID 辅助、模板插入、错误定位与预览”。若仍明显影响制作，再增加面板编辑和保存。MD 保持唯一来源，不额外维护一份剧情数据。

### 5. 音频和文档需要收口

音乐和部分音效已有真实 stream，但部署、撤退、技能、死亡、漏怪及胜负等 cue 仍有空项。规则测试无法证明听感，需要实际播放验收。

历史评审中的“无音频”“固定编队”“小黄/背景为 SVG 占位”等描述已被后续工作部分覆盖。内容编辑文档也保留旧素材映射说明；需求清单则仍将部分已有基础实现列为待办。应区分“功能已实现”和“正式体验已验收”，防止重复开发或过早勾选完成。

## 第一关建议先确定的设计问题

这些是下一项任务的决策输入，尚未选定具体方案：

1. **场景边界**：战斗发生在客厅、门口还是楼道？建议选定一个易读的小区域，让角色、路线与剧情明确对应。
2. **教学重心**：建议先教部署、格子和朝向，再由后方突破引出小黄的低费救场；技能、撤退/再部署按实际需要逐步引入。
3. **节奏长度**：以首次学习所需时间决定波次与空档，再用试玩记录检验；现有约 191 秒仅作基线。
4. **失败恢复**：建议失败后能立即重试，并通过路线和结果反馈知道哪里失守；避免依赖开发者说明。
5. **叙事一致性**：确认大星的武器、人物尺度与小黄表现；战后失踪事件应自然衔接第二关和队伍暂离。

先确认这一页设计，再制作地图、对白和资产。避免在玩法与场景尚未确定时批量重写整章。

## 工作边界

- 地图、角色、敌人、波次与剧情优先通过 content 修改。
- 通用引导若确需新增能力，先明确其职责和独立验证入口；流程触发放在 game，不让 battle 承担界面引导。
- 剧情作者工具放在 devtools；解析与诊断继续复用 game/content；播放继续复用 features/story。
- Art Test、Game Test、Player Mode 复用正式表现能力，不维护第二套战斗实现。
- 暂缓扩展第二章、技能树、金币养成、多阶段 Boss、动态改道和气候机制；它们保留为后续候选，待第一章试玩反馈后排序。
- 修复本轮暴露的问题即可，不以这次规划为由重构稳定模块或增加通用 Manager。
